# 03. 技術選定とアーキテクチャ

## 1. 基本方針

1. **静的サイトとして完結する**：サーバー処理は持たず、GitHub Pages にビルド結果を置くだけで動く。
2. **重い処理はブラウザの標準 API に任せる**：動画のデコード・エンコードは WebCodecs（ハードウェアアクセラレーション対応）、合成は WebGL2（GPU）、音声は Web Audio API。
3. **編集ロジックは UI から切り離す**：プロジェクトのデータ構造、タイムライン計算、補間などは DOM に依存しない純粋な TypeScript にする。単体テストしやすく、Worker でも同じコードを使える。
4. **プレビューと書き出しで同じ描画処理を使う**：見た目の食い違いを防ぐ。
5. **データ構造は宣言的に定義する**：オブジェクトやエフェクトのパラメータを定義データとして記述し、設定パネルの UI・保存形式の検証・補間処理をそこから自動で組み立てる。エフェクトの追加がそのまま機能追加になる構造にする。

## 3. ブラウザ対応方針

| ブラウザ            | 方針                                                                                                                      |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Chrome / Edge（PC） | 主対象。全機能を動かす                                                                                                    |
| Firefox（PC）       | WebCodecs は対応済み。File System Access API がないため保存はダウンロード方式。AAC エンコードなど一部コーデックは環境依存 |
| Safari（Mac）       | 26 以降で WebCodecs の音声も対応。保存はダウンロード方式                                                                  |
| スマホ・タブレット  | 当面対象外（起動時に案内を表示）                                                                                          |

- 機能の有無はブラウザ名ではなく **機能検出** で判定する（`'VideoEncoder' in window`、`isConfigSupported()` など）。
- WebCodecs・OPFS・File System Access API は **安全なコンテキスト（HTTPS）** が必要。GitHub Pages は HTTPS なので問題ない。

## 6. 描画パイプライン

### 6.1 1フレームの描画手順

1. **Evaluator**：シーンとフレーム番号から、その時刻に存在するオブジェクトをレイヤー順に集める。
2. 制御オブジェクトを解決する（時間制御で各オブジェクトの「素材上の時刻」を決める、グループ制御・カメラ制御で変形を合成する）。
3. 各パラメータをキーフレームから補間して確定値にする。
4. 以上をまとめた **描画ツリー（RenderGraph）** を作る。描画ツリーはただのデータで、テストで中身を検証できる。
5. **Renderer** が描画ツリーを実行する。
   - オブジェクトごとに素材のテクスチャを用意（動画フレーム・画像・テキストの描画結果・図形）
   - オブジェクト専用のバッファ上でエフェクトを順に適用（2枚のバッファを交互に使う）。ぼかし・影など描画範囲が広がるエフェクトは余白を確保する
   - 座標変換・不透明度・合成モードのシェーダーでシーンのバッファに合成
   - フィルタオブジェクトはシーンのバッファ全体にエフェクトをかける
   - シーンオブジェクトは別のバッファに再帰的に描画して素材として使う（循環参照は禁止）
6. プレビューでは Canvas に表示し、書き出しでは結果を `VideoFrame` にしてエンコーダーへ渡す。

### 6.2 色と画質

- 内部は 8bit RGBA・乗算済みアルファで合成する（最初の版）。
- プレビュー画質（自動・等倍・1/2・1/4）は内部バッファの解像度を下げて実現する。
  - 「自動」（既定）：止まっているときは等倍（フル HD より大きなシーンはフル HD 程度）で描く。再生中は 1/2 から始め、直近 20 回の描画の間隔と処理時間を見て、間に合っていなければ 1/4 へ下げ、十分に余裕があれば等倍まで上げる。
- 書き出し（動画・GIF・連番 PNG）では背景を透明にできる。WebGL2 のコンテキストをアルファ付きで作り、背景色の代わりに透明でクリアする。
- 将来の拡張：16bit 浮動小数点バッファ、リニア色空間での合成。

### 6.3 エフェクト定義の形（イメージ）

```ts
defineEffect({
  type: 'blur',
  label: 'ぼかし',
  params: {
    radius: { kind: 'number', min: 0, max: 500, default: 5, unit: 'px', animatable: true },
  },
  // 描画範囲がどれだけ広がるか
  margin: (p) => Math.ceil(p.radius * 2),
  // シェーダーのパスを組み立てる
  render: (ctx, input, p) => ctx.gaussianBlur(input, p.radius),
});
```

設定パネルは `params` から自動生成し、編集ファイルの検証や補間も同じ定義を使う。

- 実際の定義は `src/core/effects/definitions.ts`（パラメータ）と `src/engine/effects/gpu.ts`（シェーダー）に分けて書く。定義の `domain` で映像（`video`）か音声（`audio`）かを区別する。
- 時間で変わるエフェクト（振動・波打ち・ノイズ）のため、評価したパラメータには `_frame`（オブジェクト内のフレーム）・`_time`（秒）・`_seed`（エフェクト ID から作る乱数の種）も入れて渡す。同じフレームなら必ず同じ結果になるので、プレビューと書き出しで食い違わない。
- 音声波形オブジェクトは、指定したレイヤーにある音声・動画の素材内時刻を Evaluator で求め、素材の振幅データ（1 秒あたり 100 区間の最大値。タイムラインの波形表示と共用）から Canvas 2D で描く。
- LUT（`lut`）：`.cube` ファイル（3D LUT）を LUT 素材として読み込み、RGBA16F の 3D テクスチャにして色を変換する。
- ユーザー定義シェーダー（`customShader`）：利用者が書いた GLSL の関数 `vec4 effect(vec2 uv)` を、決まった宣言（`src(uv)` で元の色を読む、`uTime`・`uFrame`・`uParam1`〜`uParam4`）の間に挟んでコンパイルする。コンパイルの誤りは設定パネルに表示し、誤りがあれば何もしないエフェクトとして扱う。安全性は 16 章。
- パーティクル（`particles`）：粒子 i は「i ÷ 発生量」秒に生まれ、その後の位置・大きさ・色は i と乱数の種から計算する（`src/core/particles/`）。前のフレームの結果を使わないので、シークしても書き出しても同じ絵になる。描画は Canvas 2D で、粒子のある範囲（中心から上下左右に同じだけ）の画像にする。数の上限は 5000。

## 7. 素材の読み込みとデコード

- **取り込み**：ファイルを受け取ったら Mediabunny でコンテナを解析し、長さ・解像度・コーデック・フレームレート・音声情報を取得する。デコードできないコーデックなら、その場で理由を表示する。
- **動画**（`src/engine/media/videoFrames.ts`）：動画オブジェクトごとに Mediabunny の `VideoSampleSink`（内部で WebCodecs の `VideoDecoder`）を持つ。
  - 再生中は順番にデコードして数フレーム先読みし、再生位置の時刻に当たるフレームを表示する。大きく飛んだときはシークし直す
  - 停止中は指定時刻のフレームを正確に取り出す。連続したシーク要求（ドラッグ中など）は最後のものだけ処理する
  - `VideoFrame` は使い終わったら必ず `close()` する（GPU メモリ漏れの防止）。一定時間使われなかった読み込み口は閉じる
  - 素材の回転メタデータ（スマートフォンの縦動画など）はテクスチャ座標の変換で反映する
  - 可変フレームレートの素材は、タイムスタンプで該当するフレームを選ぶ
- **画像**：`createImageBitmap()`。
  - アニメーション画像（GIF・APNG・WebP）は `ImageDecoder` で全部のコマを読み（上限 1000 コマ）、Evaluator が再生速度・ループから求めた素材内の時刻のコマを表示する。素材の `durationSec` に 1 回分の長さを記録する。
  - 連番画像は、名前の数字の順に並べて WebM（VP9）の動画 1 本にまとめてから、動画素材として取り込む（`src/engine/media/sequence.ts`）。透明な部分のある画像はアルファも残す。まとめた動画はどこにもファイルがないので、ブラウザ（IndexedDB）に保存して次回の復元に使う。
- **字幕ファイル**（SRT・WebVTT）：時刻と文字だけを取り出し（書式のタグは除く）、字幕 1 つごとにテキストオブジェクトを作る。時刻が重なる字幕は下のレイヤーへ置く（`src/core/subtitles/`）。
- **音声**（`src/engine/audio/`）：`AudioTrackReader` が素材の区間を PCM（Float32）として読み出す（連続した区間は前回の続きからデコード）。ミキサー（`mixer.ts`）が再生位置・速度・ループに合わせて線形補間でプロジェクトのサンプリングレートへ変換し、音量・パン・フェードを適用してステレオにまとめる。ファイル全体をメモリに展開しないので長い素材も扱える。
- **音程を保った速度変更**（`src/engine/audio/timeStretch.ts`）：「速度を変えても音程を保つ」が有効なとき、WSOLA で速度を変える。出力を 50ms の粒に分け、粒 k をオブジェクト内の時刻 k × 25ms に置き、素材の対応する位置から等速で読んで窓をかけて重ねる。粒をつなぐときは、前の粒の続きと波形が最も似る位置（前後 12ms の範囲）へずらす。ずらす量は前の粒から順に決まるので、オブジェクトごとに直前の値を覚えて続きの区間に引き継ぐ（シーク直後は 4 粒前から決め直す）。
- **音声エフェクト**（`src/engine/audio/effects.ts`）：イコライザー（2 次 IIR フィルター）・コンプレッサー・ディレイ・リバーブ（並列コム＋直列オールパス）を JavaScript で処理する。音量・パン・フェードの後にオブジェクトごとにかける。
  - ミックスは区間ごと（再生 0.25 秒、書き出し 1 秒）に行うため、フィルターや残響の状態はオブジェクトごとの `AudioEffectChain` に持ち、続きの区間に引き継ぐ。区間の先頭がシーンの通し番号で前回の続きかどうかを判定する。
  - 続きでないとき（シーク直後・再生開始時）は、エフェクトごとに必要な長さ（残響が消えるまで、最大 6 秒）だけ前から処理し直して状態を作る。少し重なった区間を読み直されたとき（入れ子のシーン）は、直近の出力の履歴から返す。
  - こうすることで、区切り方・シーク位置によらず同じ音になる（単体テストで確認）。
- **サムネイル・波形**：バックグラウンドで生成してキャッシュする。
- **フォント**：システムにインストールされたフォントを名前で指定するほか、フォントファイルを素材として取り込める（`FontFace` API）。

## 8. 再生と同期

- **基準時計は音声**（`AudioContext.currentTime`）。映像は音声の時刻に合わせて表示するフレームを選び、間に合わないときはフレームを飛ばす。
- シーンの音声を 0.25 秒ずつミックスして `AudioBuffer` にし、1 秒先まで隙間なく予約再生する（`AudioPlayer.ts`）。ミキサーは書き出しと共通なので、プレビューと書き出しで音が変わらない。
- 再生中の編集は、先読み済みの 1 秒分を過ぎてから反映される。
- レベルメーターは出力を左右に分けた `AnalyserNode` から、直近約 40ms のピークと実効値を毎フレーム読む。
- 再生中は React の再描画を通さず、`requestAnimationFrame` で直接 Canvas を更新する。タイムラインの再生ヘッドも同様。

## 9. 書き出し

1. 書き出し範囲の各フレームを **1フレームずつ確実に** 描画する（再生とは異なり、デコードを待ってから描画するのでフレーム落ちしない）。
2. 描画結果を `VideoFrame` にして `VideoEncoder` へ。
   - MP4：H.264（`avc1.*`）、音声 AAC（`mp4a.40.2`）
   - WebM：VP9 / AV1、音声 Opus
   - 使えるかどうかを `isConfigSupported()` で確認し、使えない組み合わせは選択肢に出さない（例：AAC エンコーダーがない環境では WebM か Opus を提案）
3. 音声はプレビューと共通のミキサーで 1 秒ずつミックスし、`AudioEncoder` へ。映像と交互に書き込んでメモリにためすぎないようにする。
4. Mediabunny で MP4 / WebM に多重化する。
   - Chromium 系：File System Access API の書き込みストリームへ直接書き出す（大きなファイルでもメモリを圧迫しない）
   - その他：メモリ上に作ってからダウンロード（長さの上限を警告で案内）
5. 書き出しは `OffscreenCanvas` + WebGL2 の専用レンダラーで 1 フレームずつ非同期に処理し、UI を止めない（Worker 化は性能改善で検討）。進捗・残り時間・中止を表示する。中止したときは保存先のファイルを確定させない。
6. 同じ仕組みで、現在のフレームの PNG 保存と、音声のみの WAV 書き出しもできる。
7. 動画以外の形式（`src/engine/export/sequences.ts`）：
   - アニメーション GIF：指定したコマの速さ（10〜50fps）で描画し、フレームごとに 256 色（透明を使うときは 255 色＋透明）へ減色して LZW で圧縮する。表示時間は 1/100 秒単位なので、端数をためて全体の長さを合わせる。
   - 連番 PNG：1 フレームずつ PNG にし、無圧縮 ZIP にまとめる（`名前_00000.png`）。
   - 背景を透明にした動画：WebM の VP8・VP9 で、アルファを別に符号化して格納する（Mediabunny の `alpha: 'keep'`）。
   - H.265・AV1 の MP4 は、ブラウザが符号化できる環境でだけ選べる（機能検出）。

## 10. 保存・復元

詳細は [04-project-file-format.md](04-project-file-format.md)。

- **上書き保存**：File System Access API が使える場合はファイルハンドルを保持し、Ctrl+S で同じファイルに上書きする。使えない場合は毎回ダウンロード。
- **自動保存**：変更から数秒後と一定間隔で IndexedDB に保存し、次回起動時に「前回の編集を復元しますか？」と確認する。
- **素材の保持**：
  - Chromium 系：素材のファイルハンドルを IndexedDB に保存し、次回は許可を求めるだけで再び読める
  - 任意設定：素材を OPFS にコピーしておき、完全に自動で復元する（容量を消費するため選択制。`navigator.storage.persist()` で消去されにくくする）
  - 素材同梱パッケージから開いた素材：パッケージのファイルハンドルと、中の素材の位置（ZIP 内の範囲）を IndexedDB に保存し、次回はパッケージから直接読む
  - 連番画像から作った動画：動画そのものを IndexedDB に保存する
  - どれもない場合：編集ファイルを開いたときに不足素材を一覧表示し、ファイル（またはフォルダ）を投下してもらって自動照合する

## 11. 元に戻す／やり直し

- 編集操作はすべて **コマンド** を通して行う（UI から直接状態を書き換えない）。
- Immer のパッチ（変更差分と逆差分）を履歴に積む。
- ドラッグ中の連続した変更は1つの履歴にまとめる。
- 履歴の上限（例：200 件）を設ける。

## 12. ブラウザに保存する設定

プロジェクトではなく利用者ごとの設定は、`localStorage` に保存する（保存できない環境ではページを開いている間だけ有効）。

| 設定                                 | キー                   | 内容                                                                                               |
| ------------------------------------ | ---------------------- | -------------------------------------------------------------------------------------------------- |
| オブジェクト・エフェクトのプリセット | `video-editor:presets` | パラメータとエフェクトの組。JSON ファイル（`format: "vedpreset"`）として書き出し・読み込みもできる |

## 13. 性能

### 13.1 性能のための工夫

- デコード・エンコードは WebCodecs（ブラウザ内部の別スレッド）に任せる。
- テクスチャ・バッファを使い回す（テクスチャプール）。
- キャッシュはメモリ量（バイト数）で上限を決める。
- タイムラインは画面に見えている範囲だけ描画する。
- テキスト・図形などの描画結果は、見た目に関わるパラメータをキーにキャッシュする（位置・回転・不透明度だけが変わるときは描き直さない）。
- プレビュー画質「自動」で、再生中に描画が間に合わなければ解像度を下げる（6.2）。

### 13.2 Worker 化・WebGPU の検討（v1.0 時点）

1 フレームの処理時間を計測した（フル HD のシーン、Chromium。描画の時間は GPU の処理の完了まで待って計測。計測環境は GPU のないソフトウェア描画なので、描画の時間は実機より長めに出る）。

| 内容                                       | 合成の準備（CPU、ミリ秒） | 描画（ミリ秒） |
| ------------------------------------------ | ------------------------- | -------------- |
| テキスト 50 個（変化なし）                 | 0.9                       | 0.5            |
| テキスト 50 個（大きさが毎フレーム変わる） | 22.6                      | 6.4            |
| 図形 20 個＋ぼかし                         | 0.2                       | 0.5            |
| パーティクル（約 1000 粒）                 | 7.0                       | 9.2            |

分かったこと：

- 変化しない内容なら、メインスレッドの処理は 1ms 程度で、30fps の 1 フレーム（33ms）に対して十分に小さい。
- 重くなるのは「毎フレーム Canvas 2D で描き直すもの」（大きさや文字が変わるテキスト、パーティクル）で、1 個あたり約 0.5ms かかる。
- 動画のデコードは WebCodecs が別スレッドで行うので、メインスレッドの負荷にはならない。

判断：

- **Worker 化は v1.0 では行わない**。プレビュー描画を `OffscreenCanvas` ごと Worker に移すと UI の操作と描画が並行できるが、プロジェクトの状態の受け渡し（Immer のパッチを送る）、フォントの読み込み（Worker 側の `FontFace`）、素材のフレームの受け渡し（`VideoFrame`・`ImageBitmap` は転送できる）が必要になり、仕組みが大きく変わる。計測では負荷の大半が Canvas 2D の描き直しに集中しているので、まず「自動」画質と描画結果のキャッシュで対応した。描き直すオブジェクトが多いときは、その部分だけを複数の Worker で並行して描く方法が効果的で、次の段階の候補とする。
- **WebGPU 版のレンダラーは v1.0 では作らない**。現在の重い部分（Canvas 2D）は WebGPU にしても速くならない。また WebGPU は環境によって使えないことがあり、どのみち WebGL2 版を残す必要がある。描画の指示はただのデータ（`RenderOp`）なので、必要になればレンダラーだけを差し替えられる。パーティクルを GPU で計算・描画するなど、WebGPU（コンピュートシェーダー）が効く機能を足すときに改めて検討する。

ワークフローは `.github/workflows/ci.yml`。

| きっかけ                              | 実行する内容                                                   |
| ------------------------------------- | -------------------------------------------------------------- |
| すべての push・Pull Request           | 書式チェック、lint、型チェック、単体テスト、ビルド、E2E テスト |

## 16. 式とユーザー定義シェーダーの安全性

- 編集ファイルは他の人から受け取ることがあるので、中の文字列をプログラムとして実行しない。
- **式**（`src/core/expr/`）：JavaScript の `eval` や `Function` は使わず、四則演算・比較・条件・決まった関数（`sin` `clamp` `random` `noise` など）だけを持つ小さな言語として自前で構文解析・評価する。使える変数は時刻（`time` `frame` `length` `fps`）と同じオブジェクトのパラメータ、関数 `layer(番号, "パラメータ")` で別のレイヤーの値を読める。長さ（2000 文字）と入れ子の深さ（64）に上限を設け、誤りがあれば既定値を使う。
- **ユーザー定義シェーダー**：GLSL は GPU の中だけで動き、ファイルや通信には触れられない。ただし重い処理で画面が固まることはあるので、編集ファイル（パッケージを含む）を開いたときにシェーダーが含まれていれば、実行してよいかを利用者に確かめる。許可しなければ、そのエフェクトは何もしない。

## 17. PWA・多言語・配色

- **PWA**：`manifest.webmanifest` と Service Worker（`scripts/sw-template.js` をもとにビルド時に生成し、ビルドしたファイルの一覧とキャッシュ名を埋め込む）。ページはネットワークを優先し、つながらなければ保存したものを使う。新しいバージョンがあれば画面に「更新する」を表示する。インストールすると `.vedproj`・`.vedpack` を関連付け、ダブルクリックで開ける（File Handling API、`launchQueue`）。
- **多言語**：画面の文言は日本語で書き、`t('日本語', …)` で表示の言語に合わせて英語の辞書（`src/i18n/en.ts`、日本語の文言がキー）から引く。オブジェクトやエフェクトの定義に書いた名前も表示するときに訳す。辞書の抜けは単体テストで検出する（ソースの `t()` の呼び出しと定義の名前を走査する）。
- **配色**：CSS 変数で色を定義し、`data-theme` 属性でダーク・ライトを切り替える。
